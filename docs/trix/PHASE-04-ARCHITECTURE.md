# Phase 04 inspection and changes

Existing contactEnquiriesService exposes create, getById, list, updateStatus, assign, addNote, listNotes and duplicate reads. contactEnquiriesRepository provides ID/code lookup, joined user/product names and page/limit lists (default 25), filtered by type/status/state/assignment/search. TRIX will reuse and extend these reads; no mutation methods enter the tool facade.

Canonical types: PRODUCT_ENQUIRY, DEALER_ENQUIRY, DISTRIBUTION_ENQUIRY, PRODUCT_SUPPORT, GENERAL_ENQUIRY. Statuses: NEW, IN_PROGRESS, CLOSED. UUID IDs and unique TRX-ENQ-six-digit codes are stored. assigned_to is nullable users.id; NULL means unassigned. Current name is joined from users. Internal owners are MD, ADMIN or STAFF; ambiguous exact names must fail safely.

Created/updated timestamps are ISO text in SQLite and TIMESTAMPTZ in PostgreSQL; read mapping normalizes both to UTC ISO while preserving PostgreSQL milliseconds. Contact fields include full_name, phone, email, company_name, message, business address/type, city/state/pincode, territory and product/purchase context. Lists omit phone/email/message; detail bounds message and omits unrelated fields and notes. Notes exist in enquiry_notes, but bodies and actor contact details are not necessary for this phase. PostgreSQL's legacy status constraint also tolerates REVIEWED/RESPONDED, while current application types and workflows use only NEW/IN_PROGRESS/CLOSED. Unsupported stored values fail controlled output validation rather than being silently relabelled.

Real audit events exist for creation, status changes (previousStatus/newStatus), assignment (previousAssignedTo/newAssignedTo), and notes (noteId). No separate lifecycle ledger exists. Audit metadata is JSON text; a repository-owned bounded JSON projection will expose only event identity, enquiry identity/code, trusted timestamp and typed previous/new values. Malformed history yields controlled unavailable output; current updated_at is never fabricated into an event. Historical owner IDs are not reconstructed into past names.

Enquiry API uses existing data/error envelopes and requireEnquiryReadPermission (internal users except distributors), with MD/ADMIN writes. TRIX remains stricter: active MD only, fresh session check for every tool. Existing runtime limits all tools to two calls, zero retries and a 30-second timeout, and persists hashed-session/conversation execution telemetry. Extend the same internal route/response union and add a forward telemetry-only migration.

Age means max(0, server time minus createdAt), floored minutes. Date-only input covers UTC days; today is resolved on the server in Asia/Kolkata (portal business timezone), rather than model-invented dates. No approved urgency thresholds exist: attention will cover NEW+unassigned (WARNING) and broken owner reference (CRITICAL), never age-based urgency.

Phase 02 original specification is missing; its report/runtime/tests were inspected. Phase 03 live acceptance remains partial due to provider HTTP 402; the user's explicit Phase 04 request authorizes implementation, without claiming earlier live acceptance complete. Preserve all earlier capabilities and existing local changes. No final renderer, new analytics datastore, subagents or Phase 05.
